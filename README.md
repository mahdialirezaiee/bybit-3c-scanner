# اسکنر آنلاین 3C Reversal برای Bybit

این بسته برای GitHub Actions است؛ به HTML یا روشن‌بودن لپ‌تاپ نیاز ندارد. **صرف دانلود فایل، ربات را فعال نمی‌کند.** اتصال Bybit از محیط اجرای GitHub و ارسال واقعی تلگرام باید با مراحل زیر تأیید شوند. بسته هیچ معامله‌ای ثبت نمی‌کند.

## شروع

1. یک مخزن **Public** جدید با نام دلخواه، مثلاً `bybit-3c-scanner` بسازید. کد استراتژی و دادهٔ وضعیت در مخزن عمومی قابل مشاهده خواهند بود. این بسته هیچ رمز یا اطلاعات شخصی ندارد.
2. محتوای پوشه را در ریشهٔ مخزن قرار دهید: `scanner.mjs`، `engine.cjs`، `test.mjs`، `config.json` و `README.md`. ZIP را به‌تنهایی آپلود نکنید.
3. فایل `.github/workflows/scanner.yml` را با همین مسیر ایجاد کنید. اگر آپلود مرورگر پوشهٔ نقطه‌دار را منتقل نکرد، از **Add file → Create new file** استفاده کنید و نام فایل را دقیقاً `.github/workflows/scanner.yml` بگذارید و محتوای فایل هم‌نام بسته را کپی کنید.
4. وارد **Actions → Bybit 3C Scanner → Run workflow** شوید. ابتدا `mode: check-connection` را اجرا کنید. این حالت بدون توکن تلگرام، دسترسی به فهرست پرپچوال‌های USDT و کندل‌های BTCUSDT در هر ۸ تایم‌فریم را بررسی می‌کند.
5. اگر اتصال موفق بود، در **Settings → Secrets and variables → Actions → New repository secret** این دو Secret را بسازید:
   - `TELEGRAM_BOT_TOKEN`: توکن ربات خودتان.
   - `TELEGRAM_CHAT_ID`: شناسهٔ چت مقصد خودتان.
   توکن را داخل کد، README، Issue یا پیام عمومی نگذارید. ابتدا در چت ربات `/start` بفرستید.
6. `mode: telegram-test` را اجرا کنید و رسیدن پیام آزمایشی را بررسی کنید.
7. `mode: scan` را اجرا کنید. اجرای اول تاریخچه را بازسازی می‌کند و پیام وضعیت می‌فرستد؛ سیگنال‌های تاریخی آن ارسال نمی‌شوند. بعد از موفقیت، زمان‌بندی هر ۵ دقیقه فعال است.
8. در **Settings → Actions → General** اجرای workflowها باید مجاز باشد. اگر نوشتن وضعیت مجاز نبود، دسترسی **Read and write permissions** را برای workflow فعال کنید؛ قوانین شاخه نباید نوشتن در `scanner-state` را مسدود کنند.

زمان‌بندی با cron برابر `2-57/5 * * * *` است: دقیقه‌های ۲، ۷، ۱۲ و ... با زمان UTC. تأخیر GitHub و مدت اسکن به این زمان اضافه می‌شود. نیاز نیست صفحهٔ Actions باز بماند.

## چه چیزی اسکن می‌شود؟

- تمام قراردادهای **LinearPerpetual** فعال، با quote و settle برابر USDT در Bybit.
- تایم‌فریم‌های **1m، 3m، 5m، 15m، 30m، 1h، 4h، 1D**.
- تنها کندل بسته‌شده، با حاشیهٔ زمانی ۵ ثانیه و ساعت سرور Bybit.
- موتور سیگنال از HTML اصلاح‌شدهٔ قبلی منتقل شده است: سه کندل سبز → نزول بدون شکستن سقف قبلی تا لمس کف C0 → برگشت و شکست سقف C3 برای BUY؛ سه کندل قرمز قرینهٔ آن برای SELL.
- نقض با سایه قبل از تماس، حتی در کندل تماس، ستاپ را حذف می‌کند. تماس برابر با سطح C0 معتبر است؛ شکست C3 باید strict و در کندلی بعدی باشد.
- تنظیم پیش‌فرض Swing برابر ۵ و انتظار برابر ۱۵۰ کندل از C0 است.

## ذخیره، تأخیر و ارسال مجدد

شاخهٔ جداگانهٔ `scanner-state` خودکار ساخته می‌شود. فقط زمان آخرین کندل هر نماد/تایم‌فریم، صف اعلان و وضعیت اجرا در آن ذخیره می‌شود؛ توکن و Chat ID در آن نوشته نمی‌شوند. شاخهٔ اصلی دست‌نخورده می‌ماند.

در هر اجرا تاریخچهٔ لازم بازسازی می‌شود تا ترتیب منطق استراتژی حفظ شود. کندل‌های عقب‌افتاده تا ۴۸ ساعت بازیابی می‌شوند. عقب‌افتادگی بیشتر با هشدار همراه است و اعلان‌های قدیمی‌تر بازیابی نمی‌شوند. این محدودیت برای جلوگیری از اجرای بسیار طولانی است.

سیگنال‌ها قبل از ارسال در صف پایدار ذخیره می‌شوند. ارسال تأییدنشده در اجرای بعد دوباره تلاش می‌شود. با این وجود، اگر تلگرام پیام را بگیرد ولی ذخیرهٔ نتیجه قطع شود، همان پیام ممکن است تکرار شود؛ شناسهٔ ID داخل پیام برای تشخیص آن ثابت است. تضمین ارسال دقیقاً یک‌بار بین دو سرویس وجود ندارد.

اشکال دریافت یک نماد باعث پیش‌بردن زمان آن نماد نمی‌شود. وضعیت اجرا با خطا پایان می‌یابد و همان نماد در اجرای بعد دوباره بررسی می‌شود. در صورت backlog زیاد، هر اجرا حداکثر ۸۰۰ سیگنال را در پیام‌های گروهی می‌فرستد و بقیه در صف می‌مانند.

## رایگان‌بودن و محدودیت‌ها

- از مخزن **Public** و runner استاندارد `ubuntu-latest` استفاده کنید. workflow در مخزن خصوصی متوقف می‌شود؛ سهمیهٔ رایگان خصوصی برای اسکن دائمی مناسب نیست. حتی مرحلهٔ توقف ممکن است مقدار کمی از سهمیهٔ خصوصی مصرف کند.
- هیچ VPS، سرویس پولی، API key بایبیت یا سرویس ذخیرهٔ پولی لازم نیست. بسته artifact یا cache حجیم در GitHub تولید نمی‌کند.
- GitHub ممکن است اجرای زمان‌بندی‌شده را عقب بیندازد یا برخی اجراها را حذف کند. این سرویس برای اعلان فوری یک‌دقیقه‌ای تضمین ندارد.
- GitHub می‌تواند زمان‌بندی مخزن عمومیِ بدون فعالیت را پس از ۶۰ روز غیرفعال کند؛ فعال‌ماندن آن را دوره‌ای بررسی کنید. به ارسال پیام‌های ربات به‌عنوان تضمین سلامت دائمی تکیه نکنید.
- Bybit دسترسی برخی IPها/مناطق را مسدود می‌کند. محل runner استاندارد انتخاب‌پذیر نیست. اگر تست اتصال مسدود شد، این بسته روی همان runner عملیاتی نیست؛ تغییر HTML یا توکن آن را رفع نمی‌کند. بسته از پراکسی یا دورزدن محدودیت استفاده نمی‌کند.
- هیچ سرویس رایگانی با این بسته تضمین بدون قطعی یا تضمین رایگان‌ماندن همیشگی ارائه نمی‌شود.
- GitHub عمومی یعنی منطق استراتژی، سیگنال‌های صف‌شده و سوابق وضعیت هم عمومی‌اند؛ اطلاعات محرمانه فقط در Secrets باشد.

## تنظیم و توقف

`symbols: []` یعنی همهٔ نمادهای واجد شرایط؛ برای فهرست محدود مثلاً `["BTCUSDT", "ETHUSDT"]` قرار دهید. تایم‌فریم‌ها را در `config.json` تغییر دهید. تغییر Swing یا maxWait عمداً با خطا متوقف می‌شود تا وضعیت دو استراتژی مخلوط نشود: ابتدا workflow را Disable کنید، صف اعلان شاخهٔ وضعیت را بررسی کنید و پس از تعیین تکلیف پیام‌های مانده، شاخهٔ `scanner-state` را حذف کنید؛ سپس workflow را Enable و دوباره اجرا کنید. این کار تاریخچه را دوباره می‌سازد و فاصلهٔ توقف را برای اعلان بازیابی نمی‌کند.

برای توقف: **Actions → Bybit 3C Scanner → منوی سه‌نقطه → Disable workflow**. برای فعال‌سازی مجدد از همان‌جا Enable کنید. حذف Secrets روش توقف توصیه‌شده نیست.

## فایل‌ها و بررسی

`engine.cjs` موتور استراتژی؛ `scanner.mjs` دریافت داده، صف اعلان و وضعیت؛ `test.mjs` تست‌ها؛ `config.json` تنظیمات؛ `.github/workflows/scanner.yml` زمان‌بندی.

اجرای محلی تست‌ها با Node.js 20 یا جدیدتر:

```sh
node --test test.mjs
```

تست‌های خودکار، اتصال زنده و تحویل تلگرام را اثبات نمی‌کنند. برای راه‌اندازی حتماً سه مرحلهٔ اتصال، تست تلگرام و اسکن کامل را در GitHub اجرا کنید.
